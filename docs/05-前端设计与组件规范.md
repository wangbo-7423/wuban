# 05 · 前端设计与组件规范

> 上承 [02-API接口文档](./02-API接口文档.md) 与 [03-卡片协议](./03-卡片协议.md)。本文回答：**前端长什么样、组件怎么分层、状态怎么管、与后端在每个接口上传什么字段、每个字段是什么类型。**
>
> **契约真源**：`docs/02-API接口文档.md` ↔ `backend/app/schemas/*.py` ↔ `frontend/src/api/types.ts`（前端**不做 snake_case ↔ camelCase 转换**，字段名原样透传）。

---

## 1. 一句话

前端是一个**对话优先的混合界面**：中央卡片流承担学习过程，两个可拖拽的侧抽屉承担「会话导航」与「学习状态」，登录/注册三页式骨架。所有数据严格走类型契约，状态由 Pinia 接管，不写业务 magic 值。

---

## 2. 页面骨架与路由

```
/                  → 重定向到 /learn
/login             → views/Login.vue              （公开）
/register          → views/Register.vue           （公开）
/learn             → views/learn/LearnHome.vue    （默认落地，需登录）
```

| 文件 | 职责 |
| --- | --- |
| `src/router/index.ts` | `vue-router` + 路由守卫：未登录访问任何路径 → `/login`；已登录访问 `/login`/`/register` → `/learn` |
| `src/App.vue` | 极简壳，仅 `<router-view>` + 全局样式 |
| `src/main.ts` | 创建 app、注册 Pinia、Element Plus、router，启动时恢复登录态 |

> 守卫用 `localStorage.getItem('token')` 判断（兼容刷新场景），实时过期校验交给 `stores/auth.isAuthed` getter。

## 4. 组件分层

```
src/
├─ views/                       # 页面级，只组合，不写逻辑
│  ├─ Login.vue
│  ├─ Register.vue
│  └─ learn/LearnHome.vue
├─ components/
│  ├─ chat/                     # 对话域
│  │  ├─ ChatPanel.vue          # 输入 + 卡片流 + thinking + ToolTrace
│  │  ├─ CardRenderer.vue       # ★ card_type → 卡片组件 的分发器
│  │  ├─ cards/                 # 一卡一组件（见 §6）
│  │  ├─ ToolTrace.vue          # 工具调用轨迹展示
│  │  └─ WelcomeScreen.vue      # 空会话欢迎页
│  ├─ learn/                    # 学习域
│  │  ├─ ConversationList.vue   # 会话列表（新建/切换/删除）
│  │  ├─ SidePanel.vue          # 学习状态面板（右侧）
│  │  └─ EvidenceChips.vue      # 引证 chips（来源/页码/置信度）
│  └─ common/
│     └─ ResizableDrawer.vue    # 通用抽屉容器
├─ stores/                      # Pinia：auth、learn
├─ api/                         # axios 封装 + 类型契约 + 接口函数
├─ types/card.ts                # 纯前端 UI 类型（与契约无关）
├─ mocks/                       # 即真 mock（仅前端独立开发时打开）
├─ router/
├─ styles/global.scss
└─ main.ts
```

**分层规则**：
- `views/` 不写业务逻辑，只组合域组件 + 拉 store 状态。
- 域组件 props/emits 通信、强类型：`defineProps<{ msg: CardMessage }>()`，禁用 `any`（`tsconfig.json` 严格模式）。
- 跨页复用的原子组件放 `common/`。
- **纯前端 UI 类型**（`LearningContext` / `Conversation` / `DrawerState`）写在 `src/types/card.ts`，勿污染 `api/types.ts`。

## 5. 接口契约：每一个接口前端发什么、收到什么

> 字段顺序和命名是契约的一部分，前后端**严格 snake_case**；前端不做大小写转换。
> 接口均走 **`/api` 前缀**，开发环境由 Vite 代理至 `http://localhost:8000`；所有返回体都是统一三段式 `{code, message, data}`，详见 [02-API §1](./02-API接口文档.md)。

### 5.1 鉴权域 `POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me`

#### 5.1.1 注册 `POST /api/auth/register`

**前端发（`RegisterIn`）**：

| 字段 | 类型 | 必填 | 前端约束 |
| --- | --- | --- | --- |
| `username` | `string` | 是 | 3~32 位；正则 `^[a-zA-Z][a-zA-Z0-9_]*$`（字母开头，只允许字母数字下划线） |
| `nickname` | `string` | 是 | 1~32 位 |
| `password` | `string` | 是 | 8~128 位 |

```ts
// frontend/src/views/Register.vue
const payload: RegisterIn = {
  username: form.username.trim(),
  nickname: form.nickname.trim(),
  password: form.password,
}
const { token, expires_in, nickname, username } = await register(payload)
```

**后端回（`data: TokenOut`）**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `token` | `string` | 是 | JWT，前端存 `localStorage` |
| `expires_in` | `number` | 是 | 有效期秒数（默认 86400），前端据此换算成 ms 存 `token_expires_at` |
| `nickname` | `string` | 是 | — |
| `username` | `string` | 是 | — |

**业务错误**：`code=409 用户名已被占用`；`code=422 参数校验失败`（`data.error` 为字段级错误）。

注册成功 = 后端直接发 token，前端**不再调 login**，自动登录。

#### 5.1.2 登录 `POST /api/auth/login`

**前端发（`LoginIn`）**：

| 字段 | 类型 | 必填 |
| --- | --- | --- |
| `username` | `string` | 是（1~64 位） |
| `password` | `string` | 是（1~128 位） |

**后端回**：同 `TokenOut`。**业务错误**：`code=401 用户名或密码错误`（统一提示，防枚举）；`code=403 账号已被禁用`。

#### 5.1.3 当前用户 `GET /api/auth/me`

**前端发**：无 body，Bearer token 自动拦截器附上。
**后端回（`data: AuthMeOut`）**：

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 否 | 用户 UUID |
| `username` | `string` | 否 | — |
| `nickname` | `string` | 否 | — |
| `avatar_url` | `string` | 是 | 头像 URL（当前未提供上传，预留） |
| `status` | `string` | 否 | `active / banned` |
| `created_at` | `string`（ISO 8601） | 否 | — |

业务错误：`code=401`（token 缺失/过期/用户不存在）。该错误由 `axios` 响应拦截器统一处理：清 token 并 `window.location.href='/login'`。

### 5.2 学生对话域 `student`

#### 5.2.1 核心：`POST /api/student/chat`

**前端发（`ChatIn`）**：

| 字段 | 类型 | 必填 | 前端约束/默认值 |
| --- | --- | --- | --- |
| `message` | `string` | 是 | 1~4096 位，前端在 `stores/learn.send()` 中 `.trim()` |
| `images` | `ImagePart[]` | 否 | 默认 `[]`；**最多 4 张**；前端在选择图片时硬限 |
| `course_id` | `string` | 否 | 默认 `"general"`，由用户在顶栏选择后传入 |
| `conversation_id` | `string \| null` | 否 | 默认 `null`：为 `null` 时后端自动建会话（标题取 message 前 16 字） |

`ImagePart`：

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `url` | `string` | 是 | — | 公网 URL 或 `data:image/...;base64,...`（前端目前选图后转 base64） |
| `detail` | `'auto' \| 'low' \| 'high'` | 否 | `"auto"` | 识别精度 |

```ts
// stores/learn.ts.send() 节选
const payload: ChatIn = {
  message: text,
  images,
  course_id: courseId,
  conversation_id: conv.id,   // 已存在会话；不存在则先 createConversation 再发
}
const res: ChatOut = await sendChat(payload)
```

**后端回（`data: ChatOut`）**：

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `message` | `CardMessage` | 否 | **主卡片**（本次回复唯一入口，字段定义见 [03-卡片协议 §1](./03-卡片协议.md)） |
| `extras` | `CardMessage[]` | 否（`[]`） | 后续卡片（多卡输出，**预留**，当前恒空数组） |
| `thinking` | `string \| null` | 是 | GLM 思维链全文（前端可折叠展示） |
| `tool_calls` | `ToolCallRecord[]` | 否（`[]`） | 工具调用留痕 |
| `conversation_id` | `string` | 否 | 会话 id（新建时前端要更新 store） |
| `title` | `string \| null` | 是 | 会话标题（新对话场景后端会从 message 前 16 字生成） |
| `updated_context` | `unknown \| null` | 是 | 学习上下文回推，**预留**，当前为 `null` |

业务错误：`code=404 会话不存在或无权访问`（传了别人的 `conversation_id`）；`code=1002 AI 模型调用失败 / 无可用内容`。

#### 5.2.2 会话列表 `GET /api/student/conversations`

**前端发**：无 body，仅 Bearer。
**后端回（`data: ConversationOut[]`）**：

| 字段 | 类型 | 可空 | 前端如何用 |
| --- | --- | --- | --- |
| `id` | `string` | 否 | 作为 `activeId`；切换/删除的主键 |
| `course_id` | `string \| null` | 是 | 会话所属课程，前端用于在侧栏分组展示（当前未做分组） |
| `title` | `string` | 否 | 会话列表项标题；首条消息后由后端重写 |
| `created_at` | `string \| null` | 是 | ISO 8601；侧栏小字显示 |
| `updated_at` | `string \| null` | 是 | ISO 8601；侧栏排序 |

#### 5.2.3 新建会话 `POST /api/student/conversations`

**前端发（`NewConvIn`）**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `course_id` | `string` | 否 | 默认 `"general"` |
| `title` | `string \| null` | 否 | 默认 `新对话` |

**后端回（`data: ConversationOut`）**：同 5.2.2 单项。

#### 5.2.4 会话详情 `GET /api/student/conversations/{conv_id}/messages`

**前端发**：路径参数 `conv_id`。
**后端回（`data: ConversationDetail`）**：`ConversationOut` 全部字段 + `messages: CardMessage[]`（按时间正序，用户卡片与助手卡片交错）。

前端在 `stores/learn.loadMessagesFor(id)` 中调用，把 `detail.messages` 直接塞进对应会话本地缓存。

#### 5.2.5 删除会话 `DELETE /api/student/conversations/{conv_id}`

**前端发**：路径参数 `conv_id`。
**后端回（`data`）**：`{ "deleted": "<conv_id>" }`。
**业务错误**：`code=404 会话不存在`。
**前端后续动作**：从 `conversations` 数组过滤；若被删的是 `activeId`，则清空 `activeId` 并回到 `welcoming` 态。

#### 5.2.6 当前工具列表 `GET /api/student/tools`

**前端发**：无。
**后端回（`data: ToolSchema[]`）**：OpenAI function-calling 形态，供前端调试/演示「AI 能用什么」。前端**当前不消费**。

## 6. 卡片渲染映射（`CardRenderer` → 组件）

| `card_type` | 组件 | 关键 payload |
| --- | --- | --- |
| `text` / `understand` / `feedback` / `evidence` / `progress` / `warning` / `metacog` / `motivation` / `scaffold_progress` / `tool_call` | `TextCard` | `text`（Markdown/KaTeX） |

## 7. 状态管理（Pinia）

### 7.1 `stores/auth.ts`

| state | 类型 | 来源 |
| --- | --- | --- |
| `token` | `string` | `localStorage('token')` 启动时恢复 |
| `expiresAt` | `number`（ms） | `localStorage('token_expires_at')`，登录/注册时按 `expires_in * 1000` 写入 |
| `username` | `string` | `localStorage('username')` |
| `nickname` | `string` | `localStorage('nickname')` |

| getter | 行为 |
| --- | --- |
| `isAuthed` | 同时校验 token 存在 **且** 未过期（`expiresAt < Date.now()` 即过期） |

| action | 行为 |
| --- | --- |
| `login(payload: LoginIn)` | 调 `/auth/login` → 写 state + persist |
| `register(payload: RegisterIn)` | 调 `/auth/register` → 写 state + persist（注册即登录） |
| `refresh()` | 调 `/auth/me` 拉一次自己，校验 token |
| `logout()` | 清空 state + persist |

### 7.2 `stores/learn.ts`

| state | 类型 | 默认 |
| --- | --- | --- |
| `context` | `LearningContext` | `{ course:{name,subject,goal}, path:[], mastery:{}, review_due:[], cognitive:{} }` |
| `conversations` | `Conversation[]` | `[]` |
| `activeId` | `string` | `''` |
| `busy` | `boolean` | `false` |
| `welcoming` | `boolean` | `false` |
| `aborted` | `boolean` | `false` |
| `leftDrawer` / `rightDrawer` | `DrawerState` | 左开 280px / 右关 360px，可拖 |

| getter | 行为 |
| --- | --- |
| `active` | 当前 `activeId` 对应的 `Conversation` |
| `messages` | 当前活跃会话的 `CardMessage[]` |
| `isEmpty` | `!activeId \|\| welcoming \|\| conversations.length === 0` |

| action | 行为 | 关键幂等性 |
| --- | --- | --- |
| `init()` | 拉会话列表；选中第一条拉消息；无则进入欢迎态 | 仅在 `conversations.length===0` 时执行 |
| `loadMessagesFor(id)` | 调 `/conversations/{id}/messages`，回填本地 | — |
| `newConversation()` | `activeId=''`、`welcoming=true`（不发请求，首条消息时才真建） | — |
| `selectConversation(id)` | 切活跃；若本地未拉过消息则加载 | — |
| `send(message, images, courseId)` | 无会话先建 → 乐观推入用户卡片 → `POST /student/chat` → 推主卡 / 合并 `updated_context`；失败推「⚠️」卡；`busy` 期间可 `abort()` | `busy=true` 时直接 return |
| `removeConversation(id)` | 调 DELETE → 移除本地项；若是 active 则回欢迎态 | — |
| `toggleLeft/Right`、`resizeLeft/Right` | 抽屉开合 / 拖拽边界钳制 | — |

**乐观推入规则**：用户消息用本地 `id=user-<ts>` 入栈，等后端回包后**就用 `res.message.id` 占位**；本期不重排，只把真实助手卡追加到末尾。如未来要做消息重排，记住 `message.id` 是后端发来的 UUID 而不是 `user-<ts>`。

### 7.3 API 层（`src/api/`）

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 前后端**类型契约真源**：对齐 `backend/app/schemas/*.py`（每改一字段，三个文件 `schemas/*.py` ↔ `types.ts` ↔ `02-API接口文档.md` 同时改） |
| `http.ts` | axios：`baseURL='/api'`、超时 10s、请求拦截器自动附 `Authorization`、响应拦截器**解包统一响应体为 `data`**、HTTP 401 清 token 跳登录 |
| `auth.ts` / `learn.ts` | 接口函数，与 §5 表格一一对应 |
| `config.ts` | `USE_MOCK_AUTH` / `USE_MOCK_LEARN` mock 开关（当前均 `false`） |
| `../mocks/server.ts` | 真 mock（接管 axios），后端未就绪时前端可独立开发 |
| `../types/card.ts` | **纯前端 UI 类型**（`LearningContext` / `Conversation` / `DrawerState` 等），与后端无关 |

**关键陷阱**：
- 业务错误是 **HTTP 200 + `code≠0`**，**axios 拦截器不会 reject**——业务代码必须自己 `if (res.code !== 0)`。
- HTTP 401（token 失效）由拦截器统一清 token 跳 `/login`，业务无需处理。
- 解包后 `data` 已经是 `TokenOut` / `ChatOut` 等业务对象，**不要再取 `.data`**。

## 8. `ChatPanel` 交互细节

- **发送**：Enter 发送 / Shift+Enter 换行；`busy=true` 时再按 Enter 仅做 `abort()`（通过 store 的 `aborted` 标志），后端回包后追加「⏹ 已停止生成」系统卡。
- **图片**：本地选择 ≤4 张，前端用 `FileReader.readAsDataURL` 转 base64，组装成 `ImagePart[]` 随 `images` 字段上传；超 4 张直接弹 Element Plus `ElMessage.warning`。
- **过程透明**：助手卡片下方可展开 `thinking`（思维链）与 `ToolTrace`（工具调用）；每张卡右上渲染 `strategy` 策略标签（如「分解」「反例」）。
- **错误兜底**：接口失败 → store 推「⚠️ 调用 AI 失败，请稍后再试。」卡，不向用户暴露 stack/trace。
- **空态**：无会话时显示 `WelcomeScreen.vue`（欢迎语 + 三个推荐起点按钮 + 输入框同样可用，输入即自动建会话）。

## 9. 视觉与样式

- `styles/global.scss` 维护设计令牌（`var(--color-*)`、`var(--space-*)` 等），组件用 scoped 样式引用令牌，不写魔法值。
- 层级原则：聊天区为视觉主体；卡片有明确边框与类型图标；侧栏弱化、按需展开（降低外在认知负荷）。
- 关键状态**不只靠颜色表达**（兼顾色弱）；字体对比度遵循可读性优先。
- Element Plus 仅作为基础控件（按钮、输入框、抽屉、消息提示），不做品牌配色侵入。
