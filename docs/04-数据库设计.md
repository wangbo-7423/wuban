# 04 · 数据库设计

> PostgreSQL 16（强约束，禁止 SQLite fallback）。表结构真源：`backend/app/models/*.py`（SQLAlchemy 2 声明式）。schema 演进唯一路径：**Alembic**（2026-09-02 引入，app 启动自动 `upgrade head`，流程见 docs/13）。
> 本文档只描述**当前真实存在的 8 张表**；预留字段单独标注。

---

## 1. 关系图

```
users 1 ──── 1 learner_profiles        （注册即建，画像与认证解耦）
users 1 ──── * conversations           （一个用户多个会话）
conversations 1 ──── * messages        （会话内消息，整卡 JSON 落库）
learning_domains 1 ──── * learning_projects   （项目可挂学习域，可空）
users 1 ──── * learning_projects
users 1 ──── * agent_telemetry         （每轮 Agent 调用一行聚合遥测，弱关联不设外键）
users 1 ──── * learning_evidence        （过程性证据标签，mastery_evidence 工具写入）
```

## 2. 表结构

### 2.1 `users`（认证身份，最小化）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `username` | `VARCHAR(64)` | UNIQUE, INDEX | 登录名 |
| `nickname` | `VARCHAR(64)` | — | 展示昵称 |
| `password_hash` | `VARCHAR(255)` | — | bcrypt，**绝不存明文** |
| `avatar_url` | `VARCHAR(500)` | NULL | 头像（预留） |
| `status` | `VARCHAR(16)` | 默认 `active` | `active / banned` |
| `last_login_at` | `TIMESTAMPTZ` | NULL | — |
| `created_at` | `TIMESTAMPTZ` | server default now() | — |

> **刻意没有 `email`、没有 `role`**：本产品不开教师端、不用邮箱，全员 student。

### 2.2 `learner_profiles`（学习画像，与认证解耦）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `user_id` | `VARCHAR(36)` | FK→users.id, UNIQUE, INDEX | 一人一画像 |
| `learner_type` | `VARCHAR(32)` | NULL | 学习者类型（预留） |
| `goal_type` | `VARCHAR(32)` | NULL | 目标类型（预留） |
| `learning_style` | `VARCHAR(64)` | NULL | 学习风格（预留） |
| `cognitive_state` | `JSON` | NULL | **认知状态**，结构由 `backend/app/services/profile_service.py` 约定（真源），见下方 JSON 结构说明 |
| `profile_confidence` | `FLOAT` | 默认 0.0 | 画像置信度 |
| `updated_at` | `TIMESTAMPTZ` | 自动更新 | — |

> `cognitive_state` JSON 结构（与 `profile_service.py` docstring 互为真源；每轮聊天落库后 / 练习提交后全量重算回推）：
>
> ```json
> {
>   "topics": { "傅里叶变换": { "mentions": 5, "course": "signals", "last_seen": "…iso",
>               "status": "exploring | deepening | to_review",
>               "review": {"interval_days": 4, "due": "…iso"} } },
>   "misconceptions": ["…"], "preferences": ["…"],
>   "scaffolding": {"gave_answer_ratio": 0.2, "recent_scaffold_level": "…"},
>   "cognitive_load": "low | medium | high",
>   "review_queue": [{"topic": "…", "course": "…", "reason": "…", "due": "…iso", "overdue_days": 7}],
>   "practice": {"submissions": 3, "last_submit_at": "…iso"},
>   "updated_at": "…iso"
> }
> ```
>
> 复习调度为 **SM-2-lite**（`profile_service._schedule_review` 纯函数）：首次接触 2 天后安排回顾，每重新提起一次间隔翻倍（封顶 60 天），到期未碰 → `to_review` 并按超期天数进 `review_queue`（最多 8 条）；纯图谱实体无时间轴，沿用旧排期不排队。复习条目经 `GET /student/context` 折算为前端 `review_due`，点击由前端发起回忆式复习会话（不打分）。

### 2.3 `conversations`（会话）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `user_id` | `VARCHAR(36)` | FK→users.id, INDEX | 归属用户 |
| `course_id` | `VARCHAR(32)` | 默认 `general` | 建会话时的课程标识（os/autocontrol/signals/…） |
| `title` | `VARCHAR(128)` | 默认 `新对话` | 首条消息后自动取前 16 字 |
| `summary` | `TEXT` | NULL | **Write 策略·短期记忆层**：早期对话的滚动压缩摘要（LLM 合并生成），注入用压缩视图，原始消息仍全量留痕 |
| `summary_covered` | `INTEGER` | 默认 0 | 摘要已覆盖的消息条数（`messages` 按时间序的前 N 条）；压缩在此之后、最近 8 条窗口之前进行 |
| `scratchpad` | `JSON` | NULL | **Write 策略·任务状态层**：`{topic, progress, pending}`，从最新 assistant 卡启发式提取，零 LLM 成本 |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 自动 | updated_at 随消息更新 |

> 存量库迁移：已由 Alembic baseline 收编（2026-09-02 起不再需要手工 ALTER；下述历史命令仅存档）：
>
> ```sql
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary TEXT;
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary_covered INTEGER NOT NULL DEFAULT 0;
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS scratchpad JSON;
> ```

> `mastery_evidence` 工具的落点，设计见 [10-认知状态与工具边界](./10-认知状态与工具边界.md) §5.2。**只存证据标签，绝不存分数**——红线：掌握度来自过程性证据（docs/00 §6），本表是其载体，不直接等于掌握度。消费方：`profile_service.compute_cognitive_state` 聚合为 `topics[name].evidence = {type: count}`。

## 3. 设计要点

1. **身份与画像解耦**：`users` 只存认证；认知状态、目标等慢变量全在 `learner_profiles`，互不干扰。
2. **消息即卡片**：`messages` 表字段与 `CardMessage` 一一对应（JSON 列装动态载荷），历史回读直接还原卡片，不需要转换层。
3. **Agent 痕迹全留痕**：`thinking`、`tool_calls` 落库，支撑「AI 为什么这么说」的回放与审计；逐轮聚合指标另存 `agent_telemetry`（故障迭代依据，见 09 文档）。
4. **主键统一 UUID 字符串**（36 位），便于分布式与免回填。
5. **schema 变更**：改 `models/*.py` → `alembic revision --autogenerate` → **人工 review** → 启动自动 `upgrade head`（详见 docs/13）。`create_all` 已退役；从旧版本（曾有 `email/role` 列、`agent_telemetry` 可空列）升级的存量库由 baseline + b128f66432fa 迁移收编。
