# 04 · 数据库设计

> PostgreSQL 16（强约束，禁止 SQLite fallback）。表结构真源：`backend/app/models/*.py`（SQLAlchemy 2 声明式）。开发环境 `create_all` 自动建表；生产用 Alembic 迁移。
> 本文档只描述**当前真实存在的 6 张表**；预留字段单独标注。

---

## 1. 关系图

```
users 1 ──── 1 learner_profiles        （注册即建，画像与认证解耦）
users 1 ──── * conversations           （一个用户多个会话）
conversations 1 ──── * messages        （会话内消息，整卡 JSON 落库）
learning_domains 1 ──── * learning_projects   （项目可挂学习域，可空）
users 1 ──── * learning_projects
```

## 2. 表结构

### 2.1 `users`（认证身份，最小化）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `username` | `VARCHAR(64)` | UNIQUE, INDEX | 登录名 |
| `nickname` | `VARCHAR(64)` | — | 展示昵称 |
| `password_hash` | `VARCHAR(255)` | — | bcrypt，**绝不存明文** |
| `avatar_url` | `VARCHAR(500)` | NULL | 头像（预留） |
| `status` | `VARCHAR(16)` | 默认 `active` | `active / banned` |
| `last_login_at` | `TIMESTAMPTZ` | NULL | — |
| `created_at` | `TIMESTAMPTZ` | server default now() | — |

> **刻意没有 `email`、没有 `role`**：本产品不开教师端、不用邮箱，全员 student。

### 2.2 `learner_profiles`（学习画像，与认证解耦）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `user_id` | `VARCHAR(36)` | FK→users.id, UNIQUE, INDEX | 一人一画像 |
| `learner_type` | `VARCHAR(32)` | NULL | 学习者类型（预留） |
| `goal_type` | `VARCHAR(32)` | NULL | 目标类型（预留） |
| `learning_style` | `VARCHAR(64)` | NULL | 学习风格（预留） |
| `cognitive_state` | `JSON` | NULL | **认知状态**：掌握度/认知负荷/元认知校准等，结构由 Agent 侧约定 |
| `profile_confidence` | `FLOAT` | 默认 0.0 | 画像置信度 |
| `updated_at` | `TIMESTAMPTZ` | 自动更新 | — |

### 2.3 `conversations`（会话）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `user_id` | `VARCHAR(36)` | FK→users.id, INDEX | 归属用户 |
| `course_id` | `VARCHAR(32)` | 默认 `general` | 建会话时的课程标识（os/autocontrol/signals/…） |
| `title` | `VARCHAR(128)` | 默认 `新对话` | 首条消息后自动取前 16 字 |
| `summary` | `TEXT` | NULL | **Write 策略·短期记忆层**：早期对话的滚动压缩摘要（LLM 合并生成），注入用压缩视图，原始消息仍全量留痕 |
| `summary_covered` | `INTEGER` | 默认 0 | 摘要已覆盖的消息条数（`messages` 按时间序的前 N 条）；压缩在此之后、最近 8 条窗口之前进行 |
| `scratchpad` | `JSON` | NULL | **Write 策略·任务状态层**：`{topic, progress, pending}`，从最新 assistant 卡启发式提取，零 LLM 成本 |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 自动 | updated_at 随消息更新 |

> 存量库迁移（本地开发 `create_all` 只对新表生效，已有表需手工执行）：
>
> ```sql
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary TEXT;
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS summary_covered INTEGER NOT NULL DEFAULT 0;
> ALTER TABLE conversations ADD COLUMN IF NOT EXISTS scratchpad JSON;
> ```

### 2.4 `messages`（消息，卡片协议的持久化形态）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `conversation_id` | `VARCHAR(36)` | FK→conversations.id, INDEX | — |
| `role` | `VARCHAR(16)` | — | `user / assistant` |
| `card_type` | `VARCHAR(24)` | 默认 `text` | 卡片类型（16 种，见 [03-卡片协议](./03-卡片协议.md)） |
| `text` | `VARCHAR(4096)` | — | 卡片正文 |
| `payload` | `JSON` | NULL | CardPayload（math/engineering_steps/…） |
| `evidence` | `JSON` | NULL | 引证数组 |
| `confidence` | `FLOAT` | NULL | 置信度 |
| `gave_answer` | `BOOLEAN` | NULL | 是否直接给了答案 |
| `scaffold_level` | `VARCHAR(16)` | NULL | 脚手架层级 |
| `reason` | `VARCHAR(512)` | NULL | 引导理由 |
| `next_action` | `VARCHAR(16)` | NULL | 建议动作 |
| `strategy` | `JSON` | NULL | 引导策略标签数组 |
| `tool_calls` | `JSON` | NULL | 工具调用留痕数组 |
| `thinking` | `VARCHAR(8192)` | NULL | 思维链 |
| `created_at` | `TIMESTAMPTZ` | server default now() | — |

> 用户消息也走同一结构：`card_type=text`，`payload.meta` 里带 `images`（图片数组）与 `course_id`。

### 2.5 `learning_domains`（学习域）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `name` | `VARCHAR(128)` | — | 域名称 |
| `subject` | `VARCHAR(64)` | NULL | 学科 |
| `meta` | `JSON` | NULL | 附加信息 |
| `created_at` | `TIMESTAMPTZ` | server default now() | — |

### 2.6 `learning_projects`（学习项目）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK，UUID | — |
| `user_id` | `VARCHAR(36)` | FK→users.id, INDEX | 归属用户 |
| `domain_id` | `VARCHAR(36)` | FK→learning_domains.id, NULL | 可选关联 |
| `goal` | `VARCHAR(512)` | NULL | 项目目标 |
| `start_state` | `JSON` | NULL | 起点状态快照 |
| `status` | `VARCHAR(32)` | 默认 `active` | `active / paused / done` |
| `created_at` | `TIMESTAMPTZ` | server default now() | — |

## 3. 设计要点

1. **身份与画像解耦**：`users` 只存认证；认知状态、目标等慢变量全在 `learner_profiles`，互不干扰。
2. **消息即卡片**：`messages` 表字段与 `CardMessage` 一一对应（JSON 列装动态载荷），历史回读直接还原卡片，不需要转换层。
3. **Agent 痕迹全留痕**：`thinking`、`tool_calls` 落库，支撑「AI 为什么这么说」的回放与审计。
4. **主键统一 UUID 字符串**（36 位），便于分布式与免回填。
5. **schema 变更**：开发环境删库重建 `create_all`；生产必须 Alembic。从旧版本（曾有 `email/role` 列）升级的库会出现缺列，需重建或迁移。
