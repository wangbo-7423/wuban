## 1. 定位：为什么是它

### 1.1 它是「可视化策略」的完成形态

KG 四策略中的「可视化」（docs/00 §5）目前只能输出静态 ASCII/markdown 示意。交互式的差别在认知层不在呈现层：**「看图」是被动接收，「拖参数看后果」是主动做实验**——学生自己制造一次预期违背再亲手消解它，与表里反差（docs/15）是同一个失谐→解困操作，只是从语言层搬到了操作层。

### 1.2 认知科学映射（全部接现有机制）

| 原理 | 落地形态 |
| --- | --- |
| 生成效应 / 预测→验证 | `probe` 字段：「先猜 Kp 拉满会怎样，再拖」——`practice` 卡探究范式的视觉版，**不是出题** |
| 认知负荷 / segmenting | 滑块分段探索：学生按自己节奏拉出下一段信息 |
| 双重编码 | 曲线/动画 + 引导文案双通道 |
| 探索循环（docs/00 §6） | AI 提议 2~3 个「值得拖一拖的问题」由学生挑——`project_guide` 微项目同款交互模式 |

### 1.3 与个人知识库 RAG（docs/12）的优先级

**先可视化，后 RAG**：①可视化是把已承诺的四策略做满，RAG 是新开第四条知识供给线；②chunk RAG 是 table stakes 且价值兑现依赖学生上传行为（冷启动），交互封装（触发策略 + 预测结构 + 证据回流）是产品判断，抄不走；③可视化 V2/V3 的交互痕迹直接喂 `mastery_evidence` →「状态→行为」闭环，RAG 是间接喂给；④答辩演示即刻可感。RAG 保留为内容侧个性化的孤本价值（老师记号/课程范围），排第二不排除。

## 2. 三个核心设计决策

### 2.1 载体 = 新卡类型 `interactive`；渲染 = 沙箱 iframe

AI 生成的 HTML 是**不可信输入**，绝不进主页面 DOM：`<iframe sandbox="allow-scripts">`（**不带** `allow-same-origin`），整卡 JSON 落 `messages` 表沿用现有持久化。卡片协议 16 → 17 型。

### 2.2 生成分层：模板填参为主，LLM 现写为辅

不让 GLM 每次凭空写完整 HTML/JS（Flash 档手写交互 JS 方差大，1~3K token/次）：

| 层 | 覆盖 | 机制 |
| --- | --- | --- |
| 内置模板 | 高频经典概念 | 仓库内置，LLM 只传参数+文案；确定性、可测试、零生成成本 |
| `viz-kit` 内联库 | 所有模板共用 | ~10KB vanilla JS（canvas 画线 / 滑杆绑定 / 动画循环），随 HTML 内联——禁网不能挂 CDN，有它 LLM 产出更短更稳 |
| LLM 现写（`make_visual` 工具） | 长尾概念、当下语境 | 整页 HTML 现写，CSP 兜底安全 |

「模板 + 真跑 + 审阅」的形状与微项目线（`project_guide`）一脉相承。

### 2.3 触发是教学决策，不是技术开关

- 触发判据：概念有**可操纵参数**（学生能改一个状态量并立刻看到后果）；
- 与 KG `strategy_weights` 联动：可视化权重高的学科（OS/自动控制/信号）优先提议；
- 提议制：AI 给 2~3 个「值得拖一拖的问题」由学生挑，不主动塞、不打分；
- 频控：每轮至多 1 张，防刷屏；
- 落点：`prompts/guide_concept.md` 新增「何时提议可视化」段（渐进式披露已验证通路，不进 Agent.md）。

## 3. 卡片协议草案（`interactive`，P0 实施时定稿进 docs/03）

```jsonc
{
  "type": "interactive",
  "title": "PID 调参实验台",
  "html": "<!doctype html>…",              // ≤64KB；CSS/JS 全内联；零外部请求
  "preview_text": "拖动 Kp / Ki / Kd，看阶跃响应怎么变",
  "probe": {                                // 可选：预测→验证结构
    "question": "把 Kp 拉到最大，曲线会变成什么样？先猜，再拖。",
    "reveal_hint": "误差被放大后系统要经历什么？"
  },
  "meta": {
    "source": "template",                   // template | llm
    "template": "pid_tuner",                // source=template 时的模板名
    "params": {"kp": 2, "ki": 0.5, "kd": 0} // source=template 时的填参
  }
}
```

- 渲染高度 280~480px，iframe 内滚动；
- `meta.source` 进遥测，模板命中率是 §7 指标之一。

## 4. 安全模型（与 code_runner 同一哲学：Python 侧禁网，HTML 侧同样禁网）

1. `sandbox="allow-scripts"`，**无** `allow-same-origin`（opaque origin，摸不到父页 DOM/Cookie/localStorage）；
2. CSP：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:`——零外部请求；
3. 体积上限 64KB；
4. **模板守门测试**（同 KG/test_kg.py 纪律）：断言模板 HTML 无 `http(s)://` 外链、无 `fetch`/`XMLHttpRequest`、体积达标——CI 拦，不流进学生对话；LLM 现写的靠 1~3 兜底；
5. V2 回传只允许 iframe→parent 单向 `postMessage`，消息 schema 白名单（§5）。

## 5. 交互闭环：V1 → V3

| 期 | 形态 | 价值 |
| --- | --- | --- |
| **V1** | 单向展示 + 学生口头汇报观察 | 单轮体验差异即刻成立 |
| **V2** | widget `postMessage` 回传（滑过哪些值、触发什么现象）→ 前端生成「我观察到了…」一键回填消息流 | 对话重新接上，审阅式反馈有靶子 |
| **V3** | 交互遥测写 `mastery_evidence`（「拉过 Kp=100 观察到振荡」= 一条探索深度证据） | 可视化从讲解辅助升级为**过程性证据来源**，探索档案又厚一层 |

V2 消息白名单：`{type: "viz-observation", card_id, text, state}`，前端确认后入流，widget 无权直接发言。

## 9. 不做清单

| 不做 | 理由 |
| --- | --- |
| 主前端直接渲染 AI HTML（无 iframe） | XSS 红线，sandbox 隔离是安全边界，不为美观破坏 |
| 挂 CDN / 外部库（React、D3、Plotly） | 与「禁网」沙箱哲学一致；`viz-kit` 内联替代 |
| 每概念必配可视化 | 触发是教学决策（§2.3），否则成玩具 |
| V3 之前对「玩得好不好」做评价 | 打分红线（docs/00 §6），交互只留痕不判分 |
| 替换 `code_runner` 静态图 | 计算型图像（精确数值/大数据）保留，交互卡负责「操控型理解」，互补 |
| widget 内网络请求 / 表单 / 下载 | CSP + sandbox 双保险 |

## 10. 答辩口径

一句话版本：**我们把四策略里的「可视化」从静态图升级成学生亲手拖的实验——「先预测、再拖动、看后果」是生成效应与失谐消解的具身版；拖完之后，滑过了什么、看到了什么，经回传沉淀为探索档案的过程性证据，下一轮讲解因此更懂他。通用助手能给你一张图，付不起的是「实验后记住你做过什么实验」——那是教学目标函数才有的记忆。**
