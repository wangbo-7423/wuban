# 11 · 联网检索与事实核验设计

> 本文回答：**AI 伴学如何管住「算错的数、编的公式、过时的 API」这三类最伤的幻觉；联网检索什么时候用、质量怎么保障、证据怎么让学生看见；以及这一切用什么指标和实验来验证有效。**
> 代码真源：`app/agent/web_search.py`（curation 域策略）、`app/agent/tools.py`（场景装配）、`app/agent/cards.py`（证据落卡）、`app/models/telemetry.py` + `app/services/telemetry_service.py`（核验指标）。
> 上游文档：[08-工具层设计](./08-工具层设计.md)（ToolSpec 机制）、[09-Harness](./09-Harness工程设计借鉴.md)（遥测方法论）、[10-认知状态与工具边界](./10-认知状态与工具边界.md)（分层决策框架）。

## 1. 要解决的痛点（按对学生的伤害排序）

| # | 痛点 | 现状（改动前） | 伤害 |
| --- | --- | --- | --- |
| **P0** | **计算与代码幻觉**：积分算错、公式编造、「预期输出」凭空捏造 | `calculus/ode/calculator/code_runner` 工具都在，但**调不调靠模型自觉**——没有规则要求「答案里的数必须来自工具」 | 工科产品里最致命的错误形态：学生把错的数抄进作业 |
| **P1** | **事实断言幻觉**：「numpy 2.0 还有这个 API」「这定理是某某提出的」 | `web_search` 只装配在 concept 场景——**engineering 场景（版本/API 问题最密集、本地知识最不可靠）反而不给搜** | 学生按过时 API 写代码 → 报错 → 归因到「AI 讲的」 |
| **P2** | **检索质量无保障、不垂直**：通用引擎混入资讯与内容农场 | 返回什么用什么：无域评级、无重排，官方文档和营销博客平起平坐 | 搜了不如不搜；搜索结果污染讲解 |
| **P3** | **证据不可见**：来源是黑盒 | 卡片协议有 `evidence[]`、前端 `EvidenceChips` 会渲染来源角标，**但后端从不为搜索结果填充它**——链路断在最后一公里 | 学生无法核验「AI 这话哪来的」；「可解释」机制名存实亡 |

**不属于痛点的**：经典教材知识本身。CSAPP、Gonzalez《数字图像处理》这类超经典内容在模型权重里已很扎实，做成检索库边际收益低且有版权硬约束（详见 §7）。我们真正的知识缺口是**学生自己的课程语境**（讲义/课件/作业），那是另一个方案（§7.3）。

## 2. 设计原则

1. **核验不是独立模块**。生成后再跑一遍「逐句核查」意味着每轮成本与时延翻倍，且核查模型（同一个 GLM）与生成端共享知识盲区——花两倍钱买相关错误的双份自信。核验应该**分层嵌进既有 ReAct 循环**：机械可验的交给确定性工具，事实断言的交给定向检索，剩下的靠诚实声明。
2. **确定性优先**（继承 docs/10 的分层决策 checklist）：证据合并、指标统计、域评级全部是轮后确定性代码，绝不指望 LLM 自觉。
3. **工具边界不迁移**。`web_search` 的 ToolSpec（scenes 路由 / compress 摘要 / 场景指南 / 结构化失败）是 Agent 认识的接口；MCP、Tavily、ddgs 都只是这个边界之下的**可插拔后端**（见 §6）。
4. **可观测性先行**。先用遥测把「幻觉到底多严重、方案有没有效」变成数据，再决定要不要建更贵的机制（独立核查模块）——不拍脑袋。

## 3. 落地改动（v1，全部已实现）

### 3.1 场景装配：`web_search` 扩到 engineering，且默认开启（`tools.py` + `config.py`）

```python
# before: scenes=("concept",)，且 enable_web_search 默认 False（默认根本不注册！）
# after:
scenes=("concept", "engineering"), guide="guide_search.md",
description="联网搜索：核实可检验的客观事实（库/框架版本与 API 变更、发布日期、论文/著作归属、官方语法）…"
# config.py: enable_web_search: bool = True
```

两点变化：其一，engineering 是搜索收益最高的场景——版本行为、API 签名、报错归因恰是模型权重里最不可靠的部分；其二，**开关默认从 False 翻为 True**——此前「受开关限制」不是比喻，搜索工具默认压根不注册。敢默认开是因为失败语义本就是结构化降级：全部后端不可用时返回 `ok=False + hint`，GLM 用本地知识回应并声明确定度，绝不阻塞主链路；完全离线部署可设回 False。description 同时写明触发纪律（「不用于概念讲解本身」），防止模型把搜索当资料收集器。

### 3.2 检索 curation：权威域加权重排（`web_search.py`）

- 静态域表 `_DOMAIN_WEIGHTS`（纯函数、零依赖）：官方文档/标准 `1.0`（docs.python.org、numpy.org、cppreference、MDN、man7…）→ 论文/学术 `0.9~1.0`（arxiv/ieee/doi）→ edu 域 `0.9` → 百科/问答 `0.85`（wikipedia/stackoverflow）→ 技术社区 `0.5~0.8` → 内容农场 `0.1~0.4`（baijiahao、csdn 博客）；
- `_apply_domain_policy`：**稳定排序**——权威分降序、同分保持引擎原序。只做「把官方来源捞到前排」的保守干预，**不做过滤**（宁可有噪声，不空窗）；
- 每条结果带出 `authority` 字段，下游两处消费：`cards.py` 转成 `evidence.confidence`（学生看得见的来源分），遥测算权威域占比（§4）。

### 3.3 强制核验规则进场景指南（`prompts/`）

| 文件 | 新增硬规则 |
| --- | --- |
| `guide_math.md` | 答案里的任何数值/极限/通解**必须来自工具输出**；工具失败或未覆盖 → 明示「这一步未经工具验证」并给自查建议；简单口算可豁免，符号运算/多步化简/数值近似一律走工具 |
| `guide_engineering.md` | 「预期输出」必须 `code_runner` 真跑过，没跑过就明示未验证；**版本/API 行为断言先 `web_search` 核对官方文档**；学生代码报错先复现拿到真实 traceback 再解释 |
| `guide_search.md`（新增） | 只搜可检验的客观事实；概念讲解/数学推导/学生个人状态**不搜**；一轮 ≤2 次；搜不到就直说，禁止用想象中的结果填充；技术查询用英文 + 版本号；优先采信排前的官方来源 |

### 3.4 证据落卡：`format_cards` 确定性合并（`cards.py`）

- `_web_evidence(result)`：遍历本轮 `tool_calls` 里 `web_search` 的成功调用，按**域去重取 top3**，产出 `CardEvidence(source=域名, page=标题, confidence=authority)`；
- `_merge_evidence`：与切卡模型可能自带的 evidence 按 source 去重后并入**主卡**，总量封顶 5；切卡 LLM 失败走兜底单卡时同样合并——**来源呈现不依赖任何模型的自觉**；
- 前端零改动：`EvidenceChips.vue` 已渲染 `📄 域名 · 标题 (85%)`。

### 3.5 遥测：`agent_telemetry` 新增 5 列

| 列 | 含义 |
| --- | --- |
| `search_calls` | 本轮 `web_search` 调用次数 |
| `search_results` | 返回结果总数 |
| `search_authority_hits` | `authority ≥ 0.85` 的结果条数 |
| `search_top_domains` | 命中域去重列表（截断存储） |
| `bare_numeric` | 数学口径轮次，答案含数字但一个计算工具都没调（**裸算**） |

`bare_numeric` 是有意的粗口径启发式（含数字就计），只用于对比改动前后的**趋势**，不做个体审判；这些列已收编进 Alembic（迁移 `b128f66432fa` 把旧补列 hack 留下的 nullable 漂移收紧为 NOT NULL），见 docs/13。

## 4. 可量化指标（北极星与守门线）

全部指标只来自 `agent_telemetry` 单行聚合与 messages 表，一条 SQL 可复现。**这些是系统的自检数据，一律不进学生界面**（docs/00 §6 红线：不给学生对错评价）。

| # | 指标 | 口径 | 目标 | 回答什么问题 |
| --- | --- | --- | --- | --- |
| M1 | **裸算率** | `AVG(bare_numeric)` over 数学口径成功轮 | 改动后相对基线相对下降 ≥50% | P0：模型还在口算吗 |
| M2 | **权威域占比** | `SUM(search_authority_hits) / SUM(search_results)` | 消融实验中开关对比 ≥+30pp；长期 ≥60% | P2：搜到的还是内容农场吗 |
| M3 | **证据落卡率** | `search_calls>0` 且本轮任一 assistant 卡带网页 evidence 的轮 / `search_calls>0` 的轮 | ≥80% | P3：来源真的让学生看见了吗 |
| M4 | **单轮搜索次数 P95** | `MAX(search_calls)` 分轮取 P95 | ≤2 | 搜索有没有变成新的延迟黑洞 |
| M5 | **有搜索轮时延增幅** | 有/无搜索轮 `latency_ms` 的 P50 与 P95 差 | P50 增幅 ≤3s | 检索对体验的代价 |
| M6 | **搜索结构化失败率** | `search_calls` 中 `result.ok=false` 占比 | 观测值，突增即报警 | 后端链路健康度 |
| M7 | **事实错误 👎 占比**（长期） | 👎 反馈人工打标「事实错误」的占比趋势 | 持续下降；决定 §7.2 要不要建独立核查模块 | 方案是否真的压住了幻觉 |

参考 SQL（PostgreSQL）：

```sql
-- M1 裸算率（近 7 天）
SELECT 100.0 * AVG(CASE WHEN bare_numeric THEN 1 ELSE 0 END) AS bare_rate
FROM agent_telemetry
WHERE ok AND created_at > now() - interval '7 days'
  AND (allowed_tools LIKE '%calculator%' OR allowed_tools LIKE '%calculus%' OR allowed_tools LIKE '%ode%');

-- M2 权威域占比（近 7 天）
SELECT 100.0 * SUM(search_authority_hits) / NULLIF(SUM(search_results), 0) AS authority_ratio
FROM agent_telemetry
WHERE created_at > now() - interval '7 days' AND search_results > 0;

-- M5 有/无搜索轮的时延分位
SELECT (search_calls > 0) AS searched,
       percentile_cont(0.5)  WITHIN GROUP (ORDER BY latency_ms) AS p50,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY latency_ms) AS p95
FROM agent_telemetry
WHERE ok AND created_at > now() - interval '7 days'
GROUP BY 1;
```

## 5. 实验方案（判据先行，跑完就按判据裁决）

所有实验数据落 `agent_telemetry`；离线批跑用临时脚本直调 `AgentOrchestrator.run()`（同测试基建，mock 不真联网的除外）。**先跑 E0 拿基线，再上改动，否则没有对照。**

| 实验 | 设计 | 通过判据 |
| --- | --- | --- |
| **E0 基线观测**（1 周，零改动） | 线上自然流量跑 M1/M2/M4/M5/M6，落基线值 | 无判据；产出基线数字供 E1–E3 对照 |
| **E1 数学强制核验**（§3.3 math 规则） | 30 题（积分/求导/ODE 各 10）× 规则前/后各 3 次 = 180 轮；人工抽查最终数值与表达式的正确性 | M1 相对基线相对下降 ≥50%，且答案正确率不降（变化 ≤5pp） |
| **E2 事实断言核验**（§3.1+3.2+3.4） | 20 个可检验断言题（库版本行为 8 / API 签名 6 / 论文教材归属 6），web_search 开/关对照 + 人工判定对错 | 开搜索组正确率 ≥ 关搜索组 +20pp；M5 的 P50 增幅 ≤3s；M3 ≥80% |
| **E3 curation 消融**（§3.2） | 同 E2 的 20 题，域策略开/关 | 开策略组 top-3 结果的权威域占比 ≥ 关策略组 +30pp，答案正确率不降 |
| **E4 长期信号**（2~3 周线上） | 👎 反馈人工打标：事实错误 / 讲解太浅 / 其他三类，看 M7 趋势 | 事实错误占比 <20% 且连续下降 → **不建**独立核查模块；反之启动 §7.2 备选设计 |

实验纪律（继承 docs/09 警示一）：同类指标连续两周降 5pp 即视为退步信号，回滚提示词改动并归档数据。

## 6. MCP 搜索后端的定位

结论：**MCP 是 `web_search` 的后端选项，不是工具边界**。

- 边界永远是 ToolSpec：scenes 路由、compress 摘要、guide 注入、结构化失败语义都挂在它上面，Agent 与前端对后端无感；
- 优先级链：`tavily → bing → ddgs`，MCP 搜索 server（智谱四引擎 / 腾讯云 wsa / Searchpin 等）作为**可选第四档**，按 `memory_bridge` 的既有模式接入（stdio 子进程 + 会话管理 + 熔断降级）；
- **接不接的判据是大陆可达性，不是质量**：这些国产源的真实优势是百度/搜狗/必应中国的可达性；检索质量的上限由 §3.2 的 curation 层决定，与传输方式无关；
- 若未来外部工具多到需要统一网关，走 config 里预留的 `higress_gateway`，仍然是后端层的替换。

## 6.5 核实 skill：从「快查」到「断言核实流水线」（v1.1 已实现）

`web_search` 工具之上，新增横切任务型 skill **`search_verify`**（`app/skills/search_verify/`，先例 project_guide）。分工写进两者的 description，模型不会选混：

| | `web_search`（工具） | `search_verify`（skill） |
| --- | --- | --- |
| 回答的问题 | 「这个出处/链接是什么」 | 「这个断言成立吗」 |
| 形态 | 单次搜索，返回摘要 | 多步确定性流水线：剥壳构造 1~2 个查询变体（术语变体 + 清洗变体）→ 并发搜索（复用 `web_search_impl`，继承域策略与后端链）→ 并发抓取 top 1~2 权威页 → 抽取含断言关键词的证据句 → 返回证据支架 |
| 预算 | ~8s | ~12s 最坏（与 `mcp_memory_call_timeout` 同量级）；`fetch_pages=false` 时退化为快查 |

- **为什么做成 skill**：核实断言满足 skill 层的定义（多步确定性流程，单工具装不下）；一步模型调用买到整条管线，给 `MAX_TOOL_STEPS=4` 省步数；`teaching_hints` 机制在执行成功时注入 **SKILL.md 消费纪律**——结论只许三态（已核实 / 部分吻合 / 无法核实）、引用必须来自本次返回的 url、snippet_only 时结论封顶「部分吻合」、核实不改变教学法。拿到证据的同时拿到「怎么诚实地用证据」，比系统提示词常驻更精准。
- **证据支架不是结论**：`verdict_hint` 只描述证据可用性（`extracts_available / snippet_only / no_results`），三态判断由模型按纪律给出——确定性代码不下判断，与 docs/10 的分层一致。
- **失败语义**：抓页失败/抽不出句子 → `ok=true, extracts=[]` 退回摘要判断；搜索全挂 → `ok=False` + hint，模型声明确定度用本地知识回答。
- **遥测口径修正**：`_SEARCH_TOOLS = {"web_search", "search_verify"}`——M2（权威域占比）、M4（单轮搜索次数）的分子分母把 skill 调用一并计入，`results[]` 同形状（带 authority），指标定义不变。

## 7. 刻意不做与未来工作

### 7.1 经典教材 RAG —— 不做

CSAPP、Gonzalez 等超经典教材：内容已在模型权重里（RAG 边际收益低）；切片入库 + 返回原文段落是侵权使用（版权硬约束）；项目已判「此规模上向量库负收益」（docs/07 §memory）。权威性的正确实现是**出处锚点**——未来给 KG 节点加 `refs` 字段（"CSAPP §9.3"、"Gonzalez 第 3 章"），`kg_lookup` 返回时 AI 自然引用，零版权问题。

### 7.2 独立 LLM 核查模块 —— 等数据

每轮多一次全量核查 LLM 调用，成本时延翻倍且与生成端错误相关。**触发条件写死**：E4 显示事实错误 👎 占比 ≥20% 且分层核验压不住时，才启动定向核查设计（只核查「事实断言型卡片」，不做全量）。

### 7.3 用户自建知识库（`user_docs_search`）—— 下一个大件

真正垂直且无版权风险的语料是**学生自己的**讲义/课件/作业。设计占位：上传摄入管线（PDF/课件 → 切块 → GLM embedding 或本地 bge-small）→ sqlite 向量存储（单人语料规模无需 milvus）→ 注册 `user_docs_search` ToolSpec（Select 路由自动装配，编排器零改动）→ 命中结果同样走 §3.4 证据落卡。解锁场景：「对着我的讲义带我复习」「用咱们课上的记号做这道题」。

### 7.4 红线重申

`evidence.confidence` 标的是**来源可信度**，不是对学生任何形式的评分；本文全部指标只用于系统自检，不进学生界面——这是 docs/00 §6「探索循环不是测验循环」在工程侧的边界。
