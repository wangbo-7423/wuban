# 00 · AI 伴学：产品定位与认知科学设计

> 本文回答：**AI 伴学是什么业务、服务谁、做哪几类学习场景、认知心理学如何落成产品机制、边界在哪。**
> 配套：系统落地见 [01-系统架构与Agent设计](./01-系统架构与Agent设计.md)，接口契约见 [02-API接口文档](./02-API接口文档.md)。

---

## 1. 一句话定位

**AI 伴学 = 面向高校工科生的一对一 AI 学习陪伴助手。**

它不是答疑机，也不是录播课，而是像一位随身的「学长型学伴」：先了解你卡在哪，再陪你一步步把知识真正学进去——随时告诉你哪里卡、为什么卡、下一步怎么走。

| 形态 | 本质 | 一次性/长期 | 懂「这个学生」吗 | 形成关系吗 |
| --- | --- | --- | --- | --- |
| 搜索引擎 / 答疑帖 | 给答案 | 一次性 | 不懂 | 否 |
| 录播课 / 文档 | 给内容 | 一次性 | 不懂 | 否 |
| **AI 伴学** | **给「适合这个人的、看得进去的学习过程」** | **长期、持续** | **懂画像、懂进度** | **是** |

核心主张：**卖的不是内容和答案，而是「个性化 + 引导 + 反馈 + 陪伴」的学习过程。** 衡量标准不是「答得多快」，而是「学生是否真的懂了」。

## 2. 产品边界

### 2.1 明确不做的

- **不做教师端**。没有班级、课堂、审批、按班学情分析；产品只有学生一侧，所有决定由学习者本人做出。
- **不用邮箱注册**。身份就是 `username + nickname + password`，注册即用，没有任何角色选择。
- **不代写、不代劳**。不写整篇报告、不替学生跑完整项目、不把直接给答案当常态——引导优先。
- **不做心理/医学诊断**，不做绝对化的提分承诺。

### 2.2 当前做好的

注册登录 → 进入学习主界面 → 与 AI 学伴对话（可传题目图片）→ 获得**结构化卡片**形式的引导（概念解释 / 数学解题过程 / 定理含义 / 工程实操步骤 / 练习与反馈）→ 会话与学习画像持续沉淀，越用越懂你。

## 3. 目标用户与四类核心场景

目标用户是**高校工科生**（计算机、自动化、电子信息、机械等），他们的学习痛点高度集中在四类场景上，产品对每一类都有明确的「接应方式」（卡片类型 + Agent 行为规则 + 工具支持）：

| 场景 | 学生的问题 | 产品的接应 | 落地机制 |
| --- | --- | --- | --- |
| **① 概念解释** | 「虚拟内存到底是什么？」「进程和线程有啥区别？」 | 用**类比**把抽象概念挂到已有经验上，用**反例**划定概念边界，分块呈现不堆术语 | `understand` 卡 + 类比/反例/可视化策略；`kg_lookup` 查前置知识点 |
| **② 数学计算** | 「这道积分怎么算？」「帮我验算传递函数」 | 按「理解题意 → 列思路 → 计算 → 验证」**分步给**，每步带公式和说明，关键计算用工具精确求值 | `math` 卡（`problem / steps[] / answer / unit`）+ `calculator` 工具 |
| **③ 定理 / 公式的意义** | 「拉普拉斯变换为什么成立？什么时候能用？」 | 不背结论：给出**物理含义 + 适用条件 + 一个具体例子**，禁止超出条件硬套 | `understand` 卡 + system prompt 硬规则「可验证、不编造公式」 |
| **④ 工程实操** | 「做个 OS 实验：怎么加系统调用？」「搭个 PID 控制仿真」 | 步骤化指导：每步**做什么 + 命令 + 预期输出 + 常见坑**，不允许跳过前置步骤；**并配一个 20~60 分钟可完成的微项目，让学生做出看得见的产出** | `engineering` 卡（`title / command / expected / pitfalls[]`）+ `kg_lookup` 查前置 + **微项目 demo（见 §8）** |

贯穿四类场景的通用行为规则（写在 Agent 的 system prompt 里，见 01 §4）：

1. **先问再答**：问题模糊时先用 1~2 个反问帮学生定位卡点（`question` 卡），再开始解释；
2. **分步、不一次给满**：数学题和工程题分步给，每步不超过约 100 字；
3. **先肯定再纠错**：学生做错时，先肯定做对的部分，再指出问题，最后让他自己尝试修正；
4. **未知就说未知**：知识边界外的问题明示确定度低，不编造公式、不硬答。

## 4. 认知心理学 → 产品机制映射

认知心理学不是本文的「背景装饰」，而是**每个交互决策的第一性依据**。下表是当前已落地（或已留好字段位）的映射：

| 原理 | 核心主张 | 在本产品中的落地 |
| --- | --- | --- |
| **认知负荷理论**（Sweller） | 工作记忆容量有限；降低外在负荷、分块控制内在负荷 | 卡片分块呈现；system prompt 规定每步 ≤100 字；`warning` 卡提示「前置缺失/负荷过高」。判定链路：主 Agent 依据 `kg_lookup` 的前置节点推理「缺什么」，切卡模型依据回答原文 + 本轮工具摘要 + 会话状态摘要（`conversations.summary/scratchpad`，跨轮信号）归类发卡；累计掌握度驱动的规则引擎为预留演进方向（`learner_profiles.cognitive_state` 预留字段位）。跨轮状态追踪的正式设计（按概念键控的卡壳 streak）见 [17-跨轮学习状态](./17-跨轮学习状态与warning判定设计.md) |
| **图式理论 / 类比迁移** | 新知识挂到已有图式上才容易被同化 | 类比策略（进程=一栋楼、线程=楼里房间）；`kg_lookup` 返回前置节点，先补前置再讲新概念 |
| **生成效应 / 检索练习**（Roediger & Karpicke） | 自己产出答案比重复阅读记得牢 | 先反问再讲解（`question` 卡）；`practice` 卡出变式练习，`gave_answer=false` 留痕「没直接给答案」 |
| **失谐—解困 / 双联联想**（incongruity-resolution；Koestler） | 幽默与顿悟共享同一个认知操作——期望违背被消解的瞬间就是图式更新的瞬间，「啊哈」和「哈哈」是同一个动作 | **表里反差揭示式讲解**（§5.1）：先立表层、再拿表层口吻描述深层，反差自响；学生 get 到荒诞即一次零压力理解自检（不触发「考官」红线）；自发跨域关联记入探索档案（§6，最强的迁移证据） |
| **脚手架与渐隐**（Wood/Bruner/Ross） | 支持强度应随胜任度递减 | `scaffold_level: example → faded → hint → independent` 四级；练习卡 `hint_level / max_hints` 控制提示节奏 |
| **最近发展区 ZPD**（Vygotsky） | 最佳学习发生在「略高于当前水平」处 | KG 节点带 `difficulty` 与 `prerequisites`，引导顺序沿「前置已备 → 略高一级」推进 |
| **形成性反馈**（Black & Wiliam; Hattie & Timperley） | 反馈要「纠正 + 解释 + 指向下一步」，越及时越好 | `feedback` 卡：先肯定对的、指出错的、给 `next_action`；不隔夜、不空泛 |
| **元认知 / 自我调节**（Zimmerman） | 会监控自己的理解才算真会 | `metacog` 卡鼓励自查；`learner_profiles.cognitive_state` 留有掌握度/校准画像位 |
| **动机 / 成长型思维**（Deci & Ryan; Dweck） | 表扬努力与策略而非天赋，失败归因到可控因素 | `motivation` 卡；纠错话术遵循「先肯定努力/做对的部分」；学生全程主导对话节奏 |
| **可解释 / 透明** | 知道「为什么这么讲」能提升信任与迁移 | 卡片带 `reason`（为什么这样引导）、`evidence[]`（知识来源）、`confidence`；Agent 思维链 `thinking` 可展开查看 |

> 一句话：**认知负荷决定「一次给多少」，生成效应决定「先问还是先讲」，脚手架理论决定「给多强的提示」，形成性反馈决定「怎么纠错」**——它们全部物化成了卡片协议字段（见 [03-卡片协议](./03-卡片协议.md)）和 system prompt 规则，而不是停留在文档里。

## 5. 四类引导策略

Agent 在对话中按学生状态与学科特点，从策略库中选择引导方式，并在卡片上以 `strategy` 标签透出（前端渲染成小标签，学生能看见「这次用了什么教法」）：

| 策略 | 做法 | 典型适用 | 示例 |
| --- | --- | --- | --- |
| **类比** | 陌生概念 ↔ 熟悉经验建立映射 | 抽象概念、跨学科迁移 | 进程=一栋楼（独立内存），线程=楼里的房间（共享内存） |
| **分解** | 复杂问题拆成简单子问题 | 高认知负荷、多步骤问题 | 死锁拆成四个必要条件逐个击破 |
| **反例** | 呈现错误案例，划定概念边界 | 易混淆概念 | 破坏「循环等待」→ 不死锁；错误的 PV 操作 → 死锁 |
| **可视化** | 引导把抽象结构转成图/表/流程 | 结构复杂的关系 | 页表映射（逻辑页→物理帧）、状态机、根轨迹 |

策略权重按学科配置在知识图谱里（`strategy_weights`）：抽象概念多的课（操作系统、自动控制）类比/可视化权重高；结构复杂的课（信号与系统）分解/可视化权重高。消费路径：`kg_lookup` 命中时随工具结果回注，GLM 在引导时自行参考（不做硬约束）。详见 01 §6。

> 可视化策略的交互式升级——AI 生成学生可拖拽的 HTML 实验卡（`interactive` 卡，沙箱渲染、
> 预测→验证结构、交互痕迹回流探索档案）——已完成设计，见
> [16-交互可视化设计](./16-交互可视化设计.md)（待实施）。

### 5.1 表里反差：类比 / 反例的幽默叙事结构（2026-09-03 加入）

> 本节是摘要；完整设计（理论对照、探针机制、三信号观测闭环、实测数据）见
> [15-表里反差与学习信号设计](./15-表里反差与学习信号设计.md)。

不新增策略档位（KG 四策略权重与守门测试不动），而是给类比/反例在合适概念上定义一种**叙事结构**，
落地于 `prompts/guide_concept.md`（随 `kg_lookup` 装配渐进式披露）：

- **适用判据**：概念有「表层无辜、深层离谱」的双层结构——表层听着人畜无害，深层事实近乎荒诞
  （`0.1` 表层是小学加法，深层是机器里根本没有这个数；`gets()` 表层是最顺手的读入函数，
  深层是它放进来过整个互联网的蠕虫）。
- **手法核心**：决定幽默强度的是**叙述视角**，不是反差本身——**拿着表层的视角和口吻，
  把深层的事实认真地描述出来**，口吻越正经反差越响；不点破、不说「很荒诞」、不自己笑，
  反差自己会说话。
- **幽默即探针**：学生 get 到荒诞 = 深层图式已建立，这是一次**零压力的理解自检**——
  没有出题、没有判分，没 get 到也只是「不好笑」而不是「答错了」，天然守住 §6「绝不扮演考官」红线；
  没 get 到就正常补讲，**绝不解释笑点**。
- **红线**：反差必须从概念结构本身长出来，禁止外挂段子/谐音梗/网络梗
  （与材料无关的幽默是外在负荷，伤学习）；一个概念最多用一次。
- **落地（2026-09-03，双侧）**：讲解侧在 `prompts/guide_concept.md`（随 `kg_lookup` 装配注入，
  概念/数学/工程场景生效）；观测侧进记忆抽取约定——学生自发连挂数据记 relationType
  「自发关联」、接梗反应记概念 observation「表里反差探针：接住/未接住」、他觉得有意思的概念
  记「兴趣」实体；三者在 L0 常驻层与 `cognitive_state.interests` 汇合（前端侧栏「觉得有意思」
  展示），下次讲解主动往他感兴趣的方向连——这是「学长型学伴」人格温度的记忆锚点。

## 6. 业务闭环（探索循环，不是测验循环）

> **定位红线**：本循环由**学生的困惑与好奇驱动**，AI 只做「引导 + 引申 + 审阅」，
> **绝不扮演考官**——不主动出题考学生、不判分、不用「对错」衡量学习效果。
> 一旦做成「AI 出题 → 学生答 → 判分」，学生就从探索者退化成被测试者，
> **自主性**（自我决定理论中内在动机的支柱之一）会被摧毁，
> 与 §1「学长型学伴」的定位和 §2.1「学生全程主导节奏」直接冲突。

单次对话内完成一个微型探索循环，跨会话靠探索档案累积：

```
学生困惑提问（文本 / 题目图片）
   → 定位卡点（先问再答；kg_lookup 查概念节点与前置）
   → 选引导策略（类比 / 分解 / 反例 / 可视化，按学科权重）
   → 结构化讲解（understand / math / engineering 卡，分步呈现）
   → 抛出引申疑问（「你有没有想过…」，把话题主动权交还学生）
   → 学生自主选择：继续追问 ｜ 动手做微项目（见 §8）
   → 审阅式反馈（学生贴思路/代码/截图 → 指出可改进处并说明原因，不判分）
   → 沉淀（会话落库；探索档案记录「提过的好问题 / 做过的作品 / 还想深入的点」）
   ── 下一轮对话带上最近历史与档案，越用越懂这个学生
```

**为什么是「引申疑问」而不是「练习」**

让学生**提出问题**比让他回答问题更能促进深层加工——这叫**问题提出效应**
（Question Generation），是生成效应的高阶形态。AI 抛出一个「你有没有想过…」，
学生若接过去追问，说明他进入了主动探索状态；若不追问，AI 也不追着考——
**节奏始终在学生手里**。

**掌握度从哪来（不靠判分）**

掌握度是从对话过程里**观察**出来的，不是考出来的：

| 过程性证据 | 观察到什么 |
|---|---|
| 自我解释 | 学生能否用自己的话复述（自我解释效应）|
| 问题深度 | 停留在「怎么算」还是进到了「为什么」|
| 主动迁移 | 是否把知识用到新情境、举一反三 |
| 自发关联 | 没人提示，他自己把两个看似无关的东西连上了（「诶这像不像那个……」）——双联联想，最强的迁移证据 |
| 卡点时长 | 在同一个点上停留了几轮才通 |

这些都是自然对话里的信号，**不需要任何一次「出题」**。它们写进
`learner_profiles.cognitive_state`，构成的是**探索档案**，而非成绩单。

## 7. 诚实与边界（对内原则）

1. **不装懂**：模型不确定的内容要明示低置信，建议查一手资料；不编造公式、不虚构引用。
2. **引导优先但不过度**：学生明确要答案时可以给，但默认 `gave_answer=false` 留痕——
   注意「留痕」标记的是「本次没直接给答案」，**不是「出了一道题给学生做」**。
   本产品**没有「AI 出题考学生」这个环节**，详见 §6 定位红线。
3. **情感支持有限度**：鼓励话术用于调节动机，不做心理判断；遇到明显情绪困扰建议寻求真人帮助。
4. **画像可被本人否决**：`learner_profiles` 的认知状态是估计值，学生可通过 PATCH 接口修正自己的画像。

## 8. 工科微项目线：把理论变成看得见的产出

工科生的学习动机很大程度来自**胜任感**——自己做出的东西能跑、能看、能拿给别人看。
这是自我决定理论的另一根支柱，也是项目式学习（PBL）在工程教育中被反复验证的原因。
它同时回答了两个问题：**「凭什么用这个产品」**和**「怎么证明真的学会了」**。

每个重要的工程知识点，都应配一个 **20~60 分钟能做完的微项目**：

| 知识点 | 微项目示例 | 可展示产出 |
|---|---|---|
| 傅里叶变换 | 用 Python 读入一段音频，画频谱图 | 看得见的频谱图 |
| PID 控制 | 50 行代码写温控仿真，调 P/I/D 看曲线 | 可调参的仿真程序 |
| 进程调度 | 模拟 FCFS / SJF / RR，对比平均等待时间 | 对比数据 + 结论 |
| 运算放大器 | 搭反相放大电路（仿真或实物），验证增益 | 实测数据 |

**AI 在其中的角色是「项目搭档 + 审阅者」，不是出题人**：

1. **提议做什么**：给 2~3 个难度递增的选项，**由学生挑**，AI 不指定；
2. **动手时给脚手架**：先给可运行的骨架，再逐步撤掉支持（脚手架渐隐）；
3. **产出后给审阅式反馈**：「这里可以这样改，因为……」——**不判分、不打分**；
4. **沉淀为作品**：进探索档案，学生可回看、可展示。

> 这条线已落地：`project_guide` skill 内置傅里叶 / PID / 进程调度 / 运放四个**纯 Python 零依赖**的微项目模板（目标 + 脚手架 + 常见坑 + 完成标准），AI 调它拿选项给学生挑；学生贴出代码后由 `code_runner` 工具**真的跑一遍**（禁网络 / 禁系统命令 / 硬超时），AI 再给审阅式反馈。
> 它可以把已有的 `calculus` / `ode` 等求解能力串起来——从「算得对」升级到「用得上」。
