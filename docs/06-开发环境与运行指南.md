## 3. 启动顺序

### 3.1 起 PostgreSQL（端口 5433，避免和本机已有 5432 冲突）

```bash
cd backend
docker compose -f docker-compose.yml up -d
docker compose -f docker-compose.yml ps        # 应看到 ai_tutor_pg 状态 healthy
```

备选（不想装 Docker）：

```bash
# 假设本机已有 PG 16，监听 5432，请相应改 .env 的 DATABASE_URL
createdb ai_tutor    # 或用 pgAdmin 手动建库
```

### 3.2 起后端

```bash
cd backend

# ① 拷环境变量样例
cp .env.example .env
# 用编辑器填好这三项（必填，缺一项启动失败）
#   GLM_API_KEY=...
#   JWT_SECRET=至少 32 字符随机串   ← Pydantic 校验 min_length=32
#   DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5433/ai_tutor

# ② 装依赖（任选其一）
uv pip install -r <(uv pip compile pyproject.toml) --python .venv/Scripts/python.exe
# 或
pip install -e .

# ③ 跑服务（启动时自动 alembic upgrade head 建表/迁移到最新 schema）
.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000 --reload
```

打开 `http://127.0.0.1:8000/docs` 验证：自动生成的 OpenAPI；调通 `GET /api/health` 返回 `{"status":"up"}`。

**.env 关键项速查**

```ini
# ─── 必填 ─────────────────────────────────────────────
DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5433/ai_tutor
JWT_SECRET=替换为不少于 32 位的随机串
GLM_API_KEY=你的智谱 API Key

# ─── 模型（默认即可） ─────────────────────────────────
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
GLM_MODEL=glm-5.3-flash
GLM_ENABLE_THINKING=true
GLM_TIMEOUT_SEC=60
GLM_MAX_TOKENS=4096
GLM_TEMPERATURE=0.7

# ─── 工具开关 ─────────────────────────────────────────
ENABLE_CALCULATOR=true
ENABLE_WEB_SEARCH=false      # 占位，未对接 MCP
ENABLE_CODE_RUNNER=false     # 占位，未实现
```

> **缺任一必填项直接启动失败**：这是 `app/core/config.py` 的 Pydantic 校验故意做的「强约束」——绝不静默降级。

### 3.3 起前端

```bash
cd frontend
npm install
npm run dev                 # Vite 默认 5173
```

打开 `http://localhost:5173`：

- 未登录 → 自动跳 `/login`；
- 点「立即注册」→ 填 `username + nickname + password`（**无邮箱、无角色**）→ 注册成功自动登录 → 进 `/learn`。

**Vite 代理配置（已写好）**：`vite.config.ts` 里 `/api → http://localhost:8000`，所以前端只需关心 `/api/*`。

## 4. 联调约定

### 4.1 统一响应体的判断

所有接口都是 `{code, message, data}`。判断语义请按 `code` 而非 HTTP 状态：

| 你看到的 | 怎么处理 |
| --- | --- |
| HTTP 200 + `code === 0` | 成功，取 `data` |
| HTTP 200 + `code ≠ 0` | **业务错误**，按业务码处理（参考 [02 §1.3](./02-API接口文档.md) 的码表） |
| HTTP 422 | 校验失败，`data.error` 是字段 → 错误列表 映射 |
| HTTP 401 | **拦截器会清 token 跳登录页**，不需要业务代码再处理 |
| HTTP 5xx | 兜底异常，弹「⚠️ 调用失败」 |

### 4.2 登录态生命周期

| 阶段 | 行为 |
| --- | --- |
| 注册/登录成功 | 后端返回 `TokenOut`，前端存 `localStorage: token / token_expires_at / nickname / username` |
| 每次请求 | axios 请求拦截器自动附 `Authorization: Bearer <token>` |
| `token_expires_at < Date.now()` | `isAuthed === false`，路由守卫跳 `/login` |
| 后端 401 | axios 响应拦截器**统一清 token**并跳 `/login`，避免死循环 |

> 不要在前端任何业务代码里手动拼 `Authorization` 头，**它属于拦截器**。

### 4.3 跨域

开发环境前端 5173、后端 8000，**已经走 Vite 代理**，**没有 CORS 问题**。线上部署再单独配 CORS（见 §8）。

### 4.4 调试 Agent 输出

打开 DevTools Network，挑 `POST /api/student/chat` 看响应：

- `data.message` → 主卡片：注意 `card_type`、`payload`、`thinking`（GLM 思维链）、`tool_calls`（调了哪些工具、参数、结果）。
- `data.tool_calls` → 与 `message.tool_calls` 同源，前端按此渲染 `ToolTrace`。
- `data.extras` → 多卡输出，**当前恒 `[]`**，预留。

后端日志（默认 `INFO` 级别）会打印每次工具调用和文本长度；想看思维链原文也可以打 `data.thinking`。

## 5. 常见坑速查（先看这能省 30 分钟）

### 5.1 启动类

| 现象 | 大概率 | 修复 |
| --- | --- | --- |
| `pydantic.ValidationError: JWT_SECRET ... min_length=32` | secret 太短 | 生成 32 字节随机串填回 `.env` |
| `DATABASE_URL must start with postgresql` | 写成了 sqlite 或 mysql | 改回 `postgresql+psycopg2://...` |
| `GLM_API_KEY is required` | 没填 | 编辑 `.env` |
| `connection refused :5433` | PG 没起 | 跑 `docker compose -f backend/docker-compose.yml up -d` |
| 表创建失败（缺列） | 从老 schema 升级上来 | 启动即 `alembic upgrade head`；若仍报缺列，`alembic check` 看漂移，必要时补一版迁移 |

### 5.2 前端类

| 现象 | 大概率 | 修复 |
| --- | --- | --- |
| 登录后立刻被踢回 `/login` | token 没存上 / `localStorage` 被清 | 检查 `stores/auth.persist()` 是否被调用；隐身模式可能不持久 |
| 后端报错但前端显示「网络错误」 | 拦截器把 body 丢了 | 看 Network 里的 `data.message`；axios 拦截器只在 `response` 存在时才有 body |
| 进 `/learn` 是欢迎页 | 没有历史会话 | 正常，第一次进来就是欢迎页；发一句话就建会话 |
| 图片不显示 / 报 413 | base64 太大 + 后端 body size | 当前后端用默认 16MB，单张图请压到 ~1MB 以内 |
| 多模态调不通 | `images[]` 上限 | 限制 ≤4 张，前端已硬限 |
| 卡片白屏 | 新的 `card_type` 没注册到 `CardRenderer` | 在分发器里加一行映射（详见 [05 §6](./05-前端设计与组件规范.md)） |

### 5.3 Agent 类

| 现象 | 大概率 | 修复 |
| --- | --- | --- |
| 回包空、`code=1002` | GLM 报错（限流/网络/超时） | 看后端日志；增大 `GLM_TIMEOUT_SEC`、减少 thinking 链长度 |
| AI 答非所问 / 没调工具 | system prompt 没让模型决策 | 确认 `app/agent/system.py` 是否被改过 |
| 工具返回 `{"ok":false,"error":...}` | 入参校验失败 | 看后端日志的 `tool_calls[].args`；这是工具侧的**软失败**，不是抛异常，模型会换策略 |
| 卡在 `busy` 不返回 | 前端 `aborted=true` 但服务端还没回 | 调高 `MAX_TOOL_STEPS`（默认 4，`app/agent/orchestrator.py`） |
| 流式预留位还没接 | 是正常的 | 当前同步整体回包；SSE 留口（见 [01 §3 §8](./01-系统架构与Agent设计.md)） |
| 小任务的 LLM 调用 `content` 为空 | GLM 5.3 Flash **关不掉 thinking**（省略参数也是默认开），reasoning 吃光了 `max_tokens` | 小任务（分类/抽取/摘要）的 `max_tokens` 要给 reasoning 留足（实测 ≥800）；不要依赖 `enable_thinking=False` |
| `cached_tokens` 突然变 0 | 动态上下文混进了 system 消息，前缀缓存整块作废 | 动态上下文只准走 `AgentOrchestrator(dynamic_context=...)`（尾部 user 消息注入），绝不能拼进 system |

## 6. 工具扩展位

新加一个工具三步（详见 [01 §5](./01-系统架构与Agent设计.md)）：

```python
# 1) backend/app/agent/tools.py 里写函数
def my_tool(args: dict) -> dict:
    return {"ok": True, "value": ...}

# 2) 同文件加 ToolSpec（OpenAI function-calling 形态的 schema）
ToolSpec(
    name="my_tool",
    description="一句话告诉模型这个工具干啥（影响它什么时候调）",
    parameters={...},    # JSON Schema
    func=my_tool,
)

# 3) 如需总开关，在 backend/app/core/config.py 加 enable_my_tool: bool = False
#    并在 get_enabled_tools() 里读
```

不需要改前端任何东西；前端在 `/api/student/tools` 看到的工具列表会自动多一项，可选地用于调试。

## 7. 类型契约改动流程（最重要的一节）

> 改任何字段**必须三处同步**，否则会一端编译失败、另一端静默错字段。

1. 改 `backend/app/schemas/{auth,chat,card,learning}.py`（Pydantic 模型）。
2. 同步改 `frontend/src/api/types.ts` 同名 interface（**前端不做大小写转换**）。
3. 同步改 `docs/02-API接口文档.md` 或 `docs/03-卡片协议.md`（人工/AI 改都行，但**必须改**）。
4. 跑 `frontend/node_modules/.bin/tsc --noEmit -p tsconfig.json` 确认前端类型对齐。
5. 跑后端 `python -c "from app.main import app"` 确认启动没引入循环引用。
6. 改完一个字段就 commit 一次，别把多个字段改动合进同一次提交，方便回退。

完整字段改动清单见 [05 §10](./05-前端设计与组件规范.md)。
